Εγχειρίδιο

1. Επισκόπηση & Αρχιτεκτονική Εφαρμογής

Η εφαρμογή είναι σχεδιασμένη για τη δημιουργία, διαχείριση και διεξαγωγή ηλεκτρονικών ερωτηματολογίων/τεστ. Βασίζεται σε αρχιτεκτονική PHP και χρησιμοποιεί flat-file βάσεις δεδομένων.

2. Φιλοσοφία

  • Η πρόσβαση στους συμμετέχοντες πραγματοποιείται από την αρχική σελίδα με τη χρήση (α) του PIN και (β) του αριθμού μητρώου.
  • Τα κουίζ ολοκληρώνονται γρήγορα.
  • Είναι δυνατή η πολλαπλή ολοκλήρωση του ίδιου κουίζ από κάθε χρήστη.
  • Κάθε κουίζ αποτελείται από μία πληθώρα ερωτήσεων πολλαπλής επιλογής, με τέσσερις πιθανές απαντήσεις.
  • Κάθε κουίζ είναι σχεδιασμένο να περιέχει συγκεκριμένο αριθμό ερωτήσεων από το σύνολο των ερωτήσεων που είναι στη βάση δεδομένων.
  • Η επιλογή των ερωτήσεων είναι τυχαία.

3. Συμμετοχή σε κουίζ

Κάθε κουίζ έχει ένα και μοναδικό PIN, και αποθηκεύεται ως μοναδικό αρχείο στη βάση δεδομένων της εφαρμογής. Οι συμμετέχοντες μπορούν να απαντήσουν πολλές φορές ένα κουίζ, και η βαθμολογία αποθηκεύεται για κάθε προσπάθεια. Σε κάθε προσπάθεια μπορεί ο συμμετέχων να μην απαντήσει σε όλες τις ερωτήσεις. Κάθε προσπάθεια αποθηκεύει το βαθμό, το χρόνο ολοκλήρωσης και τη διεύθυνση IP.

4. Διαχείριση

Κάθε κουίζ, πέρα από το PIN, έχει και ένα PIN διαχείρισης. Το PIN διαχείρισης είναι ο μοναδικός κωδικός διαχείρισης της βάσης, και χρησιμοποιείται για επαλήθευση πριν από διαγραφή βάσης, επαλήθευση πριν από επεξεργασία, και προστασία από μη εξουσιοδοτημένη πρόσβαση. Η πρόσβαση στο περιβάλλον διαχείρισης γίνεται μέσω του πίνακα ελέγχου και διαθέσιμες είναι οι εξής λειτουργίες:

  • Δημιουργία Νέου Κουίζ όπου ο διαχειριστής ανεβάζει ένα αρχείο κουίζ.
  • Ενημέρωση Υπάρχοντος Κουίζ όπου ο διαχειριστής ανεβάζει ένα νέο αρχείο κουίζ σε αντικατάσταση του υπάρχοντος. Το PIN του κουίζ πρέπει να είναι ίδιο, ενώ το PIN διαχείρισης μπορεί να είναι διαφορετικό.
  • Αποτελέσματα όπου τα αποτελέσματα του κουίζ επιστρέφονται σαν αρχείο CSV.
  • Διαγραφή Κουίζ όπου διαγράφεται το κουίζ και όλα τα αποτελέσματα, με τη χρήση του των δύο PIN
  • Πρότυπο σχεδίασης, όπου ένα πρότυπο αρχείου κουίζ επιστρέφεται σε μορφή PHP για επεξεργασία.

5. Πρότυπο σχεδίασης κουίζ (template)

Το αρχείο πρότυπο για τη δημιουργία κουίζ έχει τα ακόλουθα πεδία, και η μορφή του αυστηρά πρέπει να είναι ίδια σε κάθε κουίζ που ανεβαίνει στην εφαρμογή. Τα πεδία πρέπει να είναι ακριβώς όπως ορίζονται. Σε κάθε περίπτωση, τα αλφαριθμητικά (strings) μπαίνουν σε εισαγωγικά π.χ. "Ερώτηση 1", και οι αριθμοί μπορούν να είναι χωρίς εισαγωγικά π.χ. CORRECT = 2. Τέλος, δεν επιτρέπονται κενές ερωτήσεις.

Κάθε κουίζ είναι ένα αρχείο τύπου INI μέσα σε PHP wrapper για ασφάλεια. Αποθηκεύεται ως: 

	PIN.ini.php

όπου PIN είναι ο μοναδικός κωδικός του κουίζ.

Το αρχείο περιέχει μία ενότητα DATABASE και πολλές ενότητες Q_x (μία για κάθε ερώτηση).

Κάθε αρχείο κουίζ προστατεύεται απο PHP Wrapper, και πρέπει υποχρεωτικά να ξεκινάει με:

	;<?php
	;die();
	;/*

και να τελειώνει με:

	*/
	;>?

6. Ενότητα DATABASE στο πρότυπο σχεδίασης

Η ενότητα [DATABASE] περιέχει τα βασικά στοιχεία του κουίζ:

  • ADMIN: PIN διαχειριστή το οποίο δεν θα πρέπει να δημοσιοποιείται σε κανένα
  • AUTHOR: Όνομα δημιουργού
  • ENTRIES: Σύνολο ερωτήσεων
  • INSTRUCTIONS: Οδηγίες που θα εμφανίζονται στους εξεταζόμενους πριν την εξέταση
  • LANGUAGE: Γλώσσα κουίζ για μελλοντική χρήση
  • PIN: PIN κουίζ που δημοσιεύεται σε κάθε συμμετέχοντα στην εξέταση
  • QUESTIONS: Πόσες ερωτήσεις καλούνται οι συμμετέχοντες να απαντήσουν σε κάθε προσπάθεια
  • TITLE: Τίτλος κουίζ
  • VERSION: Έκδοση αρχείου για προσωπικό αρχείο

Παράδειγμα ενότητας: 

	[DATABASE]
	ADMIN        = "1001"
	AUTHOR       = "Ioannis"
	ENTRIES      = "12"
	INSTRUCTIONS = "Οδηγίες εξέτασης"
	LANGUAGE     = "GR"
	PIN          = "2000"
	QUESTIONS    = "5"
	TITLE        = "Τεστ Δείγμα"
	VERSION      = "1.0"

7. Ενότητες Ερωτήσεων (Q_x) στο πρότυπο σχεδίασης

Κάθε ερώτηση έχει έναν αύξοντα αριθμό, από το 1 μέχρι και οποιοδήποτε άλλο. Κάθε ερώτηση έχει στο αρχείο ένα κομμάτι με τίτλο Q_x, όπου x ο αύξων αριθμός (π.χ. Q_34 είναι η 34η ερώτηση). Οι ερωτήσεις θα πρέπει να περιέχονται αυστηρά σε αύξοντα αριθμό, και ο συνολικός αριθμός των ερωτήσεων να αποθηκεύεται και στο πεδίο ENTRIES του μέρους DATABASE. Κάθε ερώτηση έχει τα παρακάτω πεδία:

  • TITLE: O τίτλος της ερώτησης
  • ANSWER_: ANSWER_1 μέχρι και ANSWER_4 ως οι πιθανές απαντήσεις
  • CORRECT: CORRECT ως ο αριθμός της σωστής απάντησης από το 1 μέχρι το 4

Κάθε ολοκληρωμένη ερώτηση έχει τη μορφή:

	[Q_1]
	TITLE     = "Κείμενο ερώτησης"
	ANSWER_1  = "Απάντηση 1"
	ANSWER_2  = "Απάντηση 2"
	ANSWER_3  = "Απάντηση 3"
	ANSWER_4  = "Απάντηση 4"
	CORRECT   = 2
  • Οι ερωτήσεις πρέπει να είναι σε αύξουσα σειρά (Q_1, Q_2, Q_3…)
  • Δεν επιτρέπονται κενές ερωτήσεις
  • Το CORRECT πρέπει να είναι από 1 έως 4
  • Τα strings μπαίνουν σε εισαγωγικά
  • Οι αριθμοί μπορούν να είναι χωρίς εισαγωγικά

8. Τι πρέπει να προσέχει ο δημιουργός κουίζ

  • Να μην αλλάζει τη δομή του αρχείου
  • Να μην αλλάζει τα ονόματα των πεδίων
  • Να μην αφήνει κενές ερωτήσεις
  • Να χρησιμοποιεί μόνο 1–4 στο CORRECT
  • Να μην αλλάζει το PIN μετά τη δημιουργία
  • Να μην χρησιμοποιεί ειδικούς χαρακτήρες εκτός εισαγωγικών
